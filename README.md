# SafeAngle

작업 영상의 대표 장면에서 관절을 제안받고, 사람이 확인한 좌표와 조건으로 REBA 점수와 근거 평가서를 만드는 웹 도구입니다. 법정 유해요인조사표 전체는 후속 제품 목표입니다.

팀 **솔로연합**: 고민서(엔진·백엔드), 임서현·한다현(프론트엔드·산업안전보건법 기반 기준표). 트랙은 **AI for Safety & Resilience**입니다.

## 제품 형태와 확정된 역할

이번 결과물은 **브라우저에서 사용하는 웹/웹앱**입니다. 노트북과 휴대폰에서 같은 배포 링크를 열어 사용하고, 휴대폰으로 촬영한 영상을 파일로 선택합니다. 시간 제약 때문에 iOS·Android 설치형 앱과 앱스토어 출시는 이번에 진행하지 않습니다. PWA 설치나 오프라인 앱 기능은 필수 요건으로 두지 않습니다.

2026-10-09 확정한 역할:

| 담당 | 책임 | 팀에 전달할 결과 |
| --- | --- | --- |
| 고민서 | 분석·채점 엔진과 백엔드 | 포즈·각도·품질 처리, REBA 계산, 결과 데이터 계약, AI 초안 API와 오류 처리 |
| 임서현·한다현 | 프론트엔드 | 영상 선택, 진행 상태, 근거 장면·점수 표시, 사람 확인 입력, 기준표 표시, 조사표 편집·출력 |
| 임서현·한다현 | 산업안전보건법 및 관련 규칙·고시 기반 기준표 | 공식 출처와 적용 조건이 있는 기준표, 사람이 확인할 항목, 화면 문구와 조사표 항목 연결 |

두 프론트엔드 담당자 사이의 세부 화면·기준표 분담은 팀에서 나눕니다.

## 현재 상태

2026-10-09, 비어 있는 GitHub 저장소에서 새로 시작했습니다. 현재 제품은 **GPT 대표 장면 관절 제안 → 사람의 좌표 확인·수정 → 코드의 각도·REBA 계산**입니다. 대상자 선택 → 영상 등록·작업 조건 입력 → 장면·쪽·몸 방향 선택 → 전송 동의 → 좌표 검토 → Q1~Q4 → 결과 요약·상세 평가서로 이어집니다. 목·손목과 작업 조건은 사람 확인을 유지하며, 미확인·확인 불가 입력에는 확정 점수를 내지 않습니다. **공개 웹에서 실제 Auth·DB·비공개 영상 업로드·새로고침 후 영상 복원·GPT 분석·REBA·상세 평가서 연결을 검증했습니다.** 검증 결과와 분모는 [VLM 검증 기록](docs/VLM_VERIFICATION.md), 구현·실행은 [VLM 연결 안내](docs/VLM_TRANSITION.md)를 확인하십시오. 독립 정답 대비 정확도·현장 영상은 미검증이며 개선안 생성·법정 조사표 전체는 구현하지 않았습니다.

실제 영상 분석과 점수 산출을 확인한 **[공개 웹](https://midnightsun90.github.io/SafeAngle/)**입니다. 팀이 공유한 [기존 시연 주소](https://cityboy7648-dot.github.io/SafeAngle/)도 보존하지만 해당 주소의 최신 반영 여부는 확인하지 않았습니다. `예시 사진으로 화면 둘러보기`는 실제 분석과 구별한 시안 흐름입니다.

**팀 연결 안내: [GPT 연결·실행](docs/VLM_TRANSITION.md), [REBA 계약](docs/REBA.md)**. 루트에서 `npm ci`, `npm --prefix frontend ci`를 실행하고 `.env.example`을 `.env.local`로 복사해 서버 API 키를 설정합니다. 터미널 하나에서 `npm run vision:dev`, 다른 터미널에서 `npm --prefix frontend run dev`를 실행합니다. 웹 localhost:3000, API 127.0.0.1:3212입니다. 채점은 `sceneFromVlm` → `emptyAnswers` → 사람 확인 → `scorePostureScene`입니다.

**제품의 모델 호출은 OpenAI API만 사용합니다.** 팀장이 전달한 검증 보고서의 확정 방향에 따라 `gpt-6.1-sol`로 전환했습니다. MediaPipe의 대회 허용 여부를 확인했다고 기록하지 않으며, 기존 MediaPipe 코드·테스트는 이력과 호환성 확인용으로 남깁니다. 제품 화면은 호출하지 않고 정적 빌드에서도 모델·WASM 준비를 제거했습니다.

**공개 배포 설정:** GitHub Pages와 별도 Vercel HTTPS API를 연결했습니다. repository variable `VISION_API_URL`은 `https://safeangle-api.vercel.app/api/vision`이며 허용 Origin은 `https://midnightsun90.github.io`입니다. API는 실제 Supabase 세션을 검증합니다. `OPENAI_API_KEY`는 Vercel Production Secret이고 브라우저와 Git에 넣지 않습니다. 대표 장면의 공개 API 호출은 약 26~33초였으며 이미지·좌표·점수는 탭 메모리에만 남아 새로고침 후 재분석이 필요합니다.

## 누구의 어떤 일을 줄이나

사업장의 보건관리자와 유해요인조사를 수행하는 실무자가 작업 영상을 멈춰 가며 자세를 평가하고, 평가 근거와 조사표 문장을 정리하는 일을 돕습니다.

핵심 결과는 점수 하나가 아닙니다. **어느 순간, 어느 부위 때문에 위험이 높아졌는지**를 보여 주고, 사람이 조건을 확인하고 수정한 뒤 개선안과 조사표 초안을 가져가는 흐름입니다. 현장 조사와 근로자 면담, 조사자의 최종 판단이 필요합니다.

## 사용 흐름

1. 평가 대상자를 선택하고, 옆에서 찍은 한 사람의 작업 영상을 선택합니다. 머리부터 발까지 보이게 촬영합니다. 초기 분석 범위는 최대 60초입니다.
2. 대표 장면·사람 기준 쪽·몸 방향을 선택하고 전송에 동의합니다. 선택한 JPEG 한 장만 서버를 거쳐 OpenAI API로 보냅니다. 원본 영상의 비공개 Supabase 저장과 OpenAI 장면 분석은 별도입니다.
3. GPT가 제안한 선택한 쪽의 8개 관절을 원본 위에서 확인·수정합니다. 보이지 않는 관절은 null로 남기고, 사람 확인 후 코드로 각도를 계산합니다. 다른 순간의 각도를 섞지 않습니다.
4. 목·손목 구간, 다리 지지, 하중, 손잡이 상태, 비틀림, 팔 지지, 반복·정지 같은 조건을 사람이 확인합니다. 필수 입력이 모두 확인되면 해당 장면의 REBA·조치 수준을 계산합니다. 답변 변경 시 재계산하고 장면·쪽·영상 변경 시 이전 확정 결과를 제거합니다.
5. 결과 요약과 상세 평가서에서 모델·대표 장면·GPT 원 좌표·사람 수정 좌표·채점 근거를 확인합니다.
6. 후속 제품 목표는 개선안과 법정 조사표 초안의 편집·인쇄입니다. 작업량과 작업빈도 등 면담이 필요한 칸은 사람이 채웁니다.

6은 현재 구현 범위에 포함되지 않습니다. 현재 REBA 완료를 법정 유해요인조사 전체 완료로 표시하지 않습니다.

## 꼭 지킬 것

- **점수는 규칙 엔진이 계산합니다.** OpenAI API가 각도나 REBA 점수를 정하거나 변경하지 않습니다.
- 같은 각도와 같은 사람 입력은 같은 점수를 냅니다.
- AI 제안은 사람이 확인한 뒤에만 채점 입력으로 반영합니다. 필수 조건 확인 전에는 확정 점수 없음으로 표시합니다.
- 가림, 화면 밖 관절, 정면 촬영, 지나치게 먼 촬영 등으로 측정이 어렵다면 점수 대신 재촬영 이유를 보여 줍니다.
- 손목처럼 추정이 약한 부위는 사람 확인이 필요하다고 표시합니다. 목의 중립 자세 보정도 실제 영상으로 검증합니다.
- 조사표는 **초안**입니다. 비워 둔 칸과 사람 확인이 필요한 항목을 숨기지 않습니다. REBA 결과만으로 법정 유해요인조사가 완료됐다고 표현하지 않습니다.
- 원본 영상은 팀의 비공개 Supabase 저장소에 업로드합니다(최대 50MB). 이름·작업 조건·진행 입력도 기존 DB에 저장합니다. GPT에 보내는 것은 동의한 대표 장면 한 장뿐이며, 관절 좌표·새 REBA 결과·대표 이미지는 탭 메모리에만 둡니다.
- API 키와 계정 정보는 서버 환경변수로만 다루고 Git에 넣지 않습니다.

## 프론트엔드에서 준비할 화면

페이지 이동을 최소화하고 한 페이지에서 아래 흐름을 이어 갑니다. 모바일은 영상 선택과 결과 확인이 가능하도록 배치하고, 데모는 노트북 화면을 우선합니다.

| 구간 | 필요한 화면과 동작 | 완료 기준 |
| --- | --- | --- |
| 작업 정보·영상 선택 | 작업명·공정 입력, 촬영 안내, 파일 선택·영상 미리보기 | 지원하지 않는 영상과 너무 긴 영상에 해결 방법을 안내 |

| 분석 불가 | 재촬영 사유와 촬영 방법 | 불확실한 점수가 정상 결과처럼 표시되지 않음 |

| 사람 확인 | 하중·손잡이·가감·활동 입력, 미확인 항목 표시 | 입력 변경 시 점수와 조치 수준이 다시 계산됨 |
| 기준표 | 법령·고시의 해당 조건, 출처, 사람이 확인할 정보 | REBA 평가 결과와 법령상 적용 조건을 구별해서 읽을 수 있음 |
| 초안·출력 | AI 제안, 확인 질문, 개선안, 조사표 편집, 조사자 확인, 인쇄 | 입력 변경으로 오래된 초안이 되면 다시 작성할 필요를 표시 |

AI 전송 동의는 영상 선택과 별도로 받습니다. 동의가 없거나 API가 실패하면 새 좌표와 점수를 만들지 않고 해결 방법을 안내합니다.

## 산업안전보건법 기반 기준표 작업

임서현·한다현이 만드는 기준표는 프론트엔드 문구와 엔진에 들어갈 조건의 공통 근거입니다. **법령·고시의 적용 조건, REBA 평가 규칙, 앱의 영상 품질 기준**은 각각 별도로 정리합니다. 영상 품질 임계값을 법정 기준으로 표현하지 않습니다.

### 조사할 자료와 산출물

- 산업안전보건법과 관련 규칙·고시의 공식 원문에서 적용 조건과 조사 항목을 확인합니다. 수치가 있는 조건은 단위와 이상·초과·이하·미만을 그대로 기록합니다.
- 근골격계부담작업 관련 항목은 영상에서 관찰할 수 있는 자세와, 작업시간·빈도·하중 등 사람이 확인해야 하는 조건을 구분합니다. 정보가 부족하면 후보 또는 확인 필요로 남깁니다.
- 조사표의 항목은 앱에서 채울 칸과 현장 조사·면담으로 채울 칸을 나눕니다.
- REBA는 별도의 평가 규칙표로 정리합니다. 부위별 구간과 가감 조건, 표 A/B/C, 조치 수준을 엔진 담당자와 대조합니다.
- 팀이 찾은 기준은 문서로 전달하고, 엔진 담당자가 계산 가능한 데이터로 반영합니다. 아직 작성하지 않은 문서는 완료된 자산처럼 표시하지 않습니다.

기준표에 필요한 열:

| 열 | 작성 내용 |
| --- | --- |
| 기준 ID·분류 | 항목을 가리키는 안정적인 ID, 법령·고시 / REBA / 앱 품질 기준 구분 |
| 근거 | 문서명, 조문·호·표·서식, 공식 원문 링크 |
| 버전 | 시행일 또는 발행일, 확인일 |
| 조건 | 자세, 시간, 횟수, 무게 등 필요한 조건과 단위, 조건의 결합 방식 |
| 입력 출처 | 영상 측정 / 사용자 확인 / 현장 조사·면담 |
| 정보 부족 처리 | 후보 표시, 추가 질문, 판정 보류 중 사용할 동작 |
| 화면·조사표 연결 | 표시 문구, 대응 입력칸, 조사표에 들어갈 항목 |
| 확인 상태 | 미검토 / 원문 대조 완료 / 팀 대조 완료 |

현재 팀 기준표는 `docs/evaluation-axes.md`와 `docs/confirmed-postures-and-reba-questions.md`입니다. 원문 링크와 버전을 갖춘 초안부터 전달하면 프론트엔드는 문구와 입력칸을, 백엔드는 데이터와 검증 조건을 병행해서 만들 수 있습니다.

공식 출처의 출발점:

- [산업안전보건법](https://www.law.go.kr/법령/산업안전보건법)
- [산업안전보건기준에 관한 규칙 제657조](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1028543325)
- [근골격계부담작업의 범위 및 유해요인조사 방법에 관한 고시](https://www.law.go.kr/행정규칙/근골격계부담작업의범위및유해요인조사방법에관한고시)

이 링크들은 조사 출발점입니다. 실제 기준표에 반영할 때 해당 버전과 원문 조건을 항목별로 확인합니다.

## 기술 방향과 협업 경계

현재 구현은 **Next.js + TypeScript**, **서버 전용 OpenAI Responses API**, 공유 기하·REBA 모듈입니다. 대표 장면 추출·좌표 검토·각도와 REBA는 브라우저에서 실행하고, API 키는 별도 Node 서버에만 둡니다. 개선안·법정 조사표 전체와 공개 API 배포 검증은 후속 작업입니다.

관절 추적·각도·REBA 채점과 웹 화면 연결을 구현했습니다. 초안 모듈은 아직 구현하지 않았습니다.

| 영역 | 입력 → 출력 | 구현 담당·실행 위치 |
| --- | --- | --- |
| `lib/vlm`, `server` | 대표 장면·선택한 쪽 → GPT 관절 제안 | 고민서, 서버 전용 OpenAI 호출 |
| `lib/angles` | 관절 좌표·영상 크기 → 각도·품질 | 고민서, 순수 계산 |
| `lib/reba` | 같은 장면·쪽의 각도·사람 확인값 → 점수·근거 | 고민서가 팀 기준표에 맞춰 구현, 브라우저에서 호출 |
| 초안 API(미구현) | 대표 장면·수치·작업 정보 → 초안 | 고민서, 서버 키·입력 검증·오류 처리 |
| `components`·페이지 | 엔진 결과 → 화면·확인 입력·출력 | 임서현·한다현, 웹 프론트엔드 |
| `docs/criteria.md` | 공식 원문 → 적용 조건·입력 항목·문구 | 임서현·한다현, 기준표 문서 |

원본 영상은 비공개 Supabase에 저장하고 선택한 JPEG 한 장만 동의 후 OpenAI로 전송합니다. 좌표 확인·각도·REBA는 **브라우저에서 실행**합니다. 별도 API 서버 실행 방법과 원격 빌드 설정은 [GPT 연결 안내](docs/VLM_TRANSITION.md)에 있습니다.

### 프론트엔드·엔진 연결 규격

관절 추적의 실제 타입과 함수는 `lib/types.ts`와 [엔진 연결 안내](docs/ENGINE.md), 채점 계약은 `lib/reba/types.ts`와 [REBA 연결 안내](docs/REBA.md)에 있습니다. 아래 표에서 초안 요청·응답은 아직 계약 초안입니다.

| 데이터 | 반드시 전달할 내용 |
| --- | --- |
| 작업 정보 | 작업명, 공정명, 사용자 메모, 사용자가 확인한 취급 조건 |
| 장면 분석 | 시각(초), 영상 크기, 채점하는 쪽, 관절 좌표, 부위별 각도(도), 사용 가능 여부와 이유, 손목 확인 필요 여부 |
| 사람 확인값 | 하중, 충격, 손잡이, 부위별 가감, 정지·반복·빠른 변화, 항목별 확인 상태 |
| 채점 결과 | 부위별 점수·근거, 표 A/B 값과 가산, 점수 C, 활동 점수, 최종 점수, 조치 수준, 미확인 조건 |
| 초안 요청 | 작업 정보, 대표 장면 한 장, 현재 각도·점수·확인값, 전송 동의 |
| 초안 응답 | AI 또는 기본 문장 여부, 맥락 제안, 질문, 개선안, 조사표 문장, 실패 안내 |

현재 프론트엔드는 실제 영상으로 엔진을 호출합니다. 사람 확인값 변경은 바로 재채점하며, 장면·쪽·파일 변경은 이전 확정 결과를 지웁니다. 목·손목 근사값과 측정 실패는 원본 그대로 남깁니다. 예시 데이터는 정확도 검증에 사용하지 않습니다.

### 팀 작업 방식

- 공유 타입과 공통 페이지 골격은 연결 작업 전에 고정하고, 변경이 필요하면 호출부까지 함께 반영합니다.
- 엔진 담당은 계산 결과와 실패 이유를 전달하고, 프론트엔드 담당은 별도로 점수를 재구현하지 않습니다.
- 기준표의 수치나 해석이 바뀌면 근거 문서, 엔진 테스트, 화면 문구를 함께 대조합니다.
- 각자는 작업 브랜치에서 진행하고, 합치는 변경은 관련 파일을 명시해 커밋합니다. 다른 팀원의 변경과 공유 파일 충돌을 먼저 확인합니다.
- 실행 명령과 API 연결 방법은 실제 구현이 생긴 뒤 README에 추가합니다. 아직 동작하지 않는 명령을 실행 안내로 적지 않습니다.

## 구현 순서와 완료 기준

1. **연결 기준 확정**: 고민서는 실행 환경과 공유 타입, 임서현·한다현은 화면 흐름과 기준표 초안을 준비합니다. 엔진이 준비되기 전에는 같은 예시 데이터로 화면을 연결합니다.
2. **채점·영상과 화면 병행**: 고민서는 REBA와 영상 분석을 만들고, 임서현·한다현은 결과·확인 입력·기준표 화면을 만듭니다. 공개 예제·경계값과 배포 빌드의 모델 로딩을 확인합니다.
3. **실제 연결과 초안**: 실제 엔진으로 예시 데이터를 교체합니다. 사람 입력의 재채점, AI API와 실패 처리, 조사표 편집·출력을 끝까지 연결합니다.
4. **검증과 마감**: 당일 촬영한 영상을 사람이 독립 채점합니다. 앱과 비교해 실패 사례를 고치고, 사용하지 않은 평가 장면에서 다시 확인합니다. 근거 기준표와 구현의 조건이 같은지도 대조합니다.

완료는 영상 한 편이 **점수·근거 장면·수정 가능한 조사표 초안**으로 이어지는 흐름이 실제 배포에서 동작하는 상태입니다. 품질이 부족한 영상은 재촬영으로 끝나야 합니다. 정확도는 측정한 장면 수와 분모를 함께 공개하며, 아직 측정하지 않은 일치율을 적지 않습니다.

최소 검증 항목:

- REBA 공개 예제와 경계값, 활동 점수 합산, 앉은 자세와 팔 지지 처리.
- 합성 관절 좌표의 기준 자세, 좌우 반전, 가로·세로 비율.
- 사람 없음, 가림, 화면 밖, 정면 영상의 재촬영 처리.
- 사람 입력 변경에 따른 점수와 조사표 갱신, AI 실패 시 기본 초안.
- 실제 영상에서 손 채점 대비 조치 수준 일치, 최종 점수 오차, 부위별 차이.

## 개발 도구 제한: 서브에이전트도 Codex만 사용

주최 측 추가 안내(2026-10-09, 팀장이 전달):

> Codex 사용 시 서브에이전트로 타사 모델이 호출 가능한 경우가 있습니다!
> 해당경우 페널티 및 실격이 될 수 있으니 반드시 코덱스만 사용 부탁드립니다!

팀의 개발 작업에는 **Codex만 사용**합니다. 코딩, 수정, 디버깅, 코드 리뷰를 서브에이전트에 맡길 때도 실제로 사용하는 모델이 Codex인지 확인합니다.

- Codex 화면이나 도구 안에서 실행하더라도 서브에이전트가 타사 모델을 호출하는 설정은 사용하지 않습니다.
- 외부 에이전트 연동, 모델 라우팅, 자동 대체 모델 설정을 확인하고 타사 모델 호출을 끕니다.
- 사용할 모델을 확인할 수 없는 서브에이전트는 실행하지 않고 현재 Codex 세션에서 처리합니다.
- 사용 도구와 개발 기록을 사실대로 남깁니다. 타사 모델 호출은 주최 측 안내에 따라 페널티 또는 실격 사유가 될 수 있습니다.

이 항목은 **개발 도구와 서브에이전트 사용**에 관한 안내입니다. 제품 내부의 OpenAI API와 포즈 모델 사용 범위는 결과물에 적용되는 주최 측 규정에 맞춰 별도로 확인합니다.
