# SafeAngle 피치덱

HTML/CSS로 슬라이드를 만들고 브라우저에서 PDF로 출력한다. 앱과 별도로 작업하며 빌드나 패키지 설치가 필요 없다.

## 파일 구조

- `deck.html`: 편집할 슬라이드 원본. `.slide` 하나가 PDF 한 페이지다. 현재는 16:9 제목 페이지(솔로연합), 빈 Background 페이지, Problem 초안 순서로 총 세 장이다.
- `assets/`: 실제 앱 캡처, 근거 장면, 도식, 로컬 폰트.
- `exports/`: 검수한 제출용 PDF. 최종 파일명은 `SafeAngle-pitch.pdf`.

## 제작 순서

1. 아래 순서로 메시지와 발표 분량을 확정한다.
2. `deck.html`에 슬라이드를 추가한다. 한 장에 핵심 주장 하나와 근거 화면 하나를 둔다.
3. 실제 앱 캡처를 `assets/`에 넣는다. 목업이면 목업이라고 표시한다.
4. 브라우저로 `deck.html`을 열어 화면과 발표 흐름을 확인한다.
5. Ctrl+P → PDF로 저장. 배경 그래픽 켜기, 여백 없음, 머리글·바닥글 끄기. CSS 페이지 크기를 적용하고 출력 미리보기에서 16:9 한 장에 슬라이드 하나인지 확인한다.
6. `exports/SafeAngle-pitch.pdf`로 저장하고 페이지 수, 한글 글꼴, 이미지, 잘림을 확인한다. 다른 PC에서도 확인한다.

영상과 애니메이션은 PDF에서 재생되지 않으므로 핵심 장면을 정지 화면으로 넣는다. 시연 링크나 QR은 보조 수단으로 사용한다.

## 구성 초안

| 장 | 핵심 메시지 | 필요한 자료 | 발표 시간 제안 |
| --- | --- | --- | --- |
| 1 | SafeAngle이 누구의 어떤 일을 돕는가 | 제품명, 한 문장 소개 | 15초 |
| 2 | 작업 영상에서 평가 근거를 찾아 정리하는 과정이 번거롭다 | 기존 업무 흐름, 확인된 사용자 근거 | 30초 |
| 3 | 영상 → 위험 장면 → 상세 평가서 → 조사표 초안 | 제품 흐름 도식 | 30초 |
| 4 | 관리자가 보는 실제 사용 흐름 | 실제 앱 캡처 또는 데모 | 65초 |
| 5 | 점수의 근거를 검토하고 사람이 확인한다 | 상세 평가서, 확인 필요 입력 | 35초 |
| 6 | 지금 구현·검증한 범위 | 실행 결과와 테스트, 미확인 항목 | 35초 |
| 7 | 도입 가치와 다음 검증 | 기대 효과, 현장 검증 계획 | 20초 |

시간은 팀 제안이며 합계 3분 50초다. 시연 시간도 포함한다. 정확도·시간 절감·사용자 수 등 수치는 검증 자료가 있을 때만 넣는다. 목표 기능과 실제 구현은 구분한다.

## 제출 기준의 출처

저장소의 `docs/HACKATHON.md`에 따르면 발표용 PDF 한 파일이 필수이며 1차 발표·데모 합계는 4분이다. 최종 제출 조건은 담당 팀원이 확인한 현장 안내를 따른다. 이 폴더에는 아직 최종 PDF가 없다.
