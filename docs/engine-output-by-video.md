# 영상별 엔진 출력 항목

## 목적과 범위

- 대상 영상: `lift_transfer`(낮은 곳에서 높은 곳으로 옮기기), `seated_handwork`(앉아서 손 작업하기), `push_pull`(밀거나 당기기).
- 엔진은 **관찰한 장면의 수치와 측정 가능 여부**만 반환한다. `좋음/나쁨`, REBA 부위별 점수, 최종 점수, 법적 판정은 반환하지 않는다.
- 세 영상에 서로 다른 모델이나 각도 정의를 쓰지 않는다. 공통 출력 형식은 같고, 영상별로 결과 화면에서 우선 볼 항목만 다르다.
- 현재 제품 화면과 엔진은 연결되지 않았다. 이 문서는 연결할 때의 출력 계약이다. 영상 식별자와 DB 저장은 제품 연결 단계에서 추가한다.

기준 문서: [평가축](evaluation-axes.md), [촬영 자세와 질문](confirmed-postures-and-reba-questions.md), [엔진 계약과 한계](ENGINE.md), [현재 DB](DATABASE.md).

## 1. 모든 영상에서 내야 할 값

엔진은 영상 전체를 분석하고, **장면마다 실제 분석 시각**을 붙인다. 현재 기본 분석 간격은 0.1초다. 화면과 DB는 사람이 선택한 **같은 시각의 장면**에서 필요한 값을 읽는다. 서로 다른 시각의 부위별 최대값을 한 자세로 합치지 않는다.

| 출력 항목 | 단위·값 | 현재 엔진 | 용도 |
| --- | --- | --- | --- |
| `posture_type`, 영상 식별자 | 세 자세 중 하나, 해당 업로드 영상 | 화면·DB가 연결 시 부여 | 결과가 어느 영상에서 왔는지 확인 |
| `time_sec` | 실제 분석된 영상 시각, 초 | `frames[].timeSec` | 선택 장면과 영상 위치 연결 |
| `person_count` | 검출된 사람 수 | `frames[].personCount` | 0명·다중 인물 장면 구분 |
| `facing` | 화면상 방향 `-1`/`1`/`null` | 영상 결과의 `facing` | 부호가 필요한 각도 해석 |
| `side` | 사람 기준 `left`/`right` | 양쪽 모두 측정 | 왼쪽·오른쪽 측정값을 섞지 않음 |
| `trunk_deg` | 몸통 기울기, 도 | 양쪽 `measurements.trunk.value` | R05 |
| `neck_deg` | 몸통 대비 목 기울기 **근삿값**, 도 | 양쪽 `measurements.neck.value` | R02 |
| `knee_flexion_deg` | 무릎 굽힘, 도. 곧게 펴면 0° | 양쪽 `measurements.knee.value` | R09 |
| `upper_arm_deg` | 몸통 대비 위팔 각도, 도 | 양쪽 `measurements.upperArm.value` | R10 |
| `elbow_flexion_deg` | 팔꿈치 굽힘, 도. 곧게 펴면 0° | 양쪽 `measurements.lowerArm.value` | R14 |
| `wrist_flexion_deg` | 손목 굽힘 **근삿값**, 도. 곧게 펴면 0° | 양쪽 `measurements.wrist.value` | R15의 사람 확인 자료 |
| 각 부위의 `status`, `reasons`, `approximate` | `measured`/`unavailable`, 실패 이유 코드, 근사 여부 | 각 `Measurement` | 빠진 값을 0°로 오인하지 않음 |
| 장면의 `requires_review`, `tracking_warnings` | 재확인 여부와 추적 경고 코드 | 각 `TrackedFrame` | 추적이 끊기거나 대상이 바뀐 구간 표시 |
| 영상의 `duration_sec`, `sample_interval_sec`, `measurement_coverage` | 초, 초, 부위별 측정 장면 비율 | 영상 결과 | V01·V03·V05와 누락 범위 표시 |
| `model_version`, `package_version`, `analyzed_at` | 실행에 사용한 모델·패키지·시각 | `runtime` | 같은 결과를 다시 해석할 때 버전 확인 |

각도는 **영상 평면의 추정값**이다. 현재 엔진에는 별도 `head_deg`가 없다. 머리 방향이나 실제 3차원 목 회전 각도를 `neck_deg`로 바꾸어 부르지 않는다. 현재 `lowerArm`은 팔꿈치 **굽힘**이므로, 나중에 REBA의 아래팔 내각 구간과 비교한다면 같은 장면에서 `180° - elbow_flexion_deg`로 변환해야 한다. 이 변환도 엔진의 새 측정값이 아니다.

`value = null`이면 `status = unavailable`과 이유를 함께 전달한다. 각도 소수점의 표시 자리수는 화면에서 정하고, 저장값은 임의로 점수 구간에 맞춰 반올림하지 않는다. `minVisibility`는 위치 정확도의 백분율이 아니므로 좋음/나쁨 확률로 표시하지 않는다.

## 2. 영상별 필수 출력과 우선 확인 항목

세 영상 모두 **1절의 공통값 전체**를 반환한다. 아래 표는 생략 가능한 값의 목록이 아니라, 각 영상에서 결과 화면이 먼저 보여 줄 각도와 시각이다.

| 영상 | 우선 볼 정량 출력 | 확인할 장면 | 엔진에 요구하지 않는 판정 |
| --- | --- | --- | --- |
| **1. 들어 옮기기** `lift_transfer` | 시간별 몸통·목·양쪽 무릎 굽힘, 양쪽 위팔·팔꿈치 각도. 선택 장면의 같은 값과 측정 불가 이유 | 물건을 집는 순간, 들어 올리는 동안, 올려놓는 순간 중 사람이 실제 작업을 대표하는 장면 선택 | 물체 무게·실제 힘, 다리 지지 상태, 팔 지지·비틀림, 위험 점수 |
| **2. 앉아서 손 작업** `seated_handwork` | 시간별 목·몸통, 양쪽 위팔·팔꿈치·손목 근사 각도. 선택 장면의 같은 값과 손목 가림·근사 여부 | 실제 손 작업과 팔 지지 상태를 사람이 확인할 수 있는 장면 선택 | 앉음 여부 확정, 손가락 동작·키보드 사용량, 팔 지지, 작업 중 반복 횟수·지속시간 확정 |
| **3. 밀기·당기기** `push_pull` | 시간별 몸통·목, 양쪽 위팔·팔꿈치·무릎 각도. 선택 장면의 같은 값과 방향·추적 경고 | 손으로 힘을 가하는 실제 순간을 사람이 선택. 몸을 크게 돌려 측면 각도가 성립하지 않으면 그 장면은 측정 불가 | 밀기·당기기 힘의 크기, 수레 무게를 힘으로 환산, 한쪽 다리 지지, 손잡이 상태, 위험 점수 |

영상 1의 집기·올리기, 영상 2의 팔 지지·작은 반복, 영상 3의 힘을 쓰는 순간은 **현재 엔진이 자동으로 붙이는 동작 이름이 아니다**. 그 구간의 시각은 사람이 선택하거나, 별도로 검증한 장면 선택 기능이 필요하다. 현재 각도 시계열만으로 작업 종류나 실제 하중을 확정하지 않는다.

## 3. 평가축과 출력 책임

| 평가축 | 처리 |
| --- | --- |
| R02·R05·R09·R10·R14 | 엔진의 목·몸통·무릎·위팔·팔꿈치 각도와 측정 상태를 사용 |
| R15 | 손목 근사 각도를 제시하고 사람이 구간을 확인. 안 보이면 `null`과 이유 유지 |
| R01 | 장면 시각은 엔진, 평가할 팔의 선택은 사람 입력 |
| R03·R04·R06~R08·R11~R13·R16~R22 | 기존 질문·현장 확인에서 받음. 엔진의 숫자로 확정하거나 빈 값을 `아니요`로 바꾸지 않음 |
| R23~R26 | 평가표 문서에는 REBA 계산·조치 수준이 남아 있지만, **현재 제품 방향에서는 최종 점수를 만들지 않음**. 엔진 출력에서도 제외 |
| R27 | 선택 장면·측정값·사람 답변·미확인 이유를 결과 화면에 표시. 항목별 `좋음/나쁨` 판단은 나중에 정할 별도 규칙이 담당 |
| V01~V05 | 사람 수·영상 길이·부위별 누락·방향/추적 경고 등 **현재 측정 가능한 신호**만 전달. 밝기·흔들림 등의 검사를 구현하지 않았다면 통과로 표시하지 않음 |
| B01~B11·S01~S16 | 영상 각도만으로 완료 처리하지 않음. 작업 시간·환경·증상·실제 힘 등은 별도 입력·조사 |

## 4. DB와 결과 화면으로 넘기는 최소 기록

현재의 `assessment_videos`에는 영상 위치, `assessment_posture_inputs`에는 선택 시각과 사람 답변이 있다. 추가할 자세별 **측정 결과 기록**은 현재 흐름에서 평가 1건·자세 1종당 선택 장면 1건으로 둔다.

| 저장할 값 | 이유 |
| --- | --- |
| `assessment_id`, `posture_type`, 분석한 영상의 `storage_path` | 다른 평가·다른 영상 결과와 혼동 방지 |
| 실제 `time_sec`, 사람 기준 `side`, 양쪽의 6개 각도 | 화면의 부위별 수치와 좌우 비교에 사용 |
| 각 부위의 측정 상태·이유·근사 여부, 장면 추적 경고 | 수치가 없는 이유와 사람이 확인할 항목 표시 |
| 분석 모델·출력 계약 버전, 분석 시각 | 모델을 바꾼 뒤 이전 결과 구분 |

값의 형식은 DB 열, 별도 측정 행, 구조화된 데이터 중 구현 시 선택할 수 있다. **전달 항목과 단위는 위 표대로 고정**한다. 전체 영상의 모든 프레임과 33개 관절 좌표를 이 결과 행에 복사할 필요는 없다. 장면을 다시 고르면 해당 시각의 값을 다시 추출하고 기존 결과를 갱신한다. 영상이 교체되면 이전 측정 결과를 무효로 한다.

결과 화면은 각 영상의 **선택 장면 시각 → 측정한 부위별 각도 → 측정 불가·근사 이유 → 사람이 답한 조건**을 같은 자세 안에서 연결한다. 항목별 `좋음/나쁨` 판정 기준은 나중에 별도로 정하고, 그 전에는 측정 수치만 보여 준다. 세 영상의 각도를 합산하거나 최종 점수를 만들지 않는다.

## 5. 현재 구현과 연결할 때 필요한 일

1. 현재 `analyzeVideo(file)` 결과에서 위 공통값을 꺼내는 변환기를 만든다. 엔진은 지금 브라우저에서 실행되며 DB에는 쓰지 않는다.
2. 사람이 선택한 시각에서 가장 가까운 분석 프레임을 찾되, 차이가 **실제 샘플 간격의 절반 이내**일 때만 연결한다. DB와 화면에는 요청 시각이 아닌 프레임의 실제 `timeSec`를 기록한다. 범위를 벗어나면 그 시각을 다시 분석하거나 장면을 다시 선택한다.
3. 선택 장면 측정값을 DB에 저장하고 새로고침 뒤 다시 읽는다. 영상 교체·장면 변경 시 결과 무효화 또는 재분석을 한다.
4. 항목별 판단 기준이 확정되면 별도 규칙으로 수치·사람 답변을 해석한다. 엔진의 `ready`/`partial`은 **측정 완전성** 상태이지 자세의 좋음/나쁨이 아니다.
