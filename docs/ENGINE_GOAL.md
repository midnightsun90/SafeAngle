## 3. 포즈 모델과 데이터 처리

- 기본 모델은 현재 고정된 @mediapipe/tasks-vision 0.10.34와 MediaPipe Pose Landmarker Full v1이다. 공식 SDK·모델 문서와 설치한 타입을 확인해 구현한다. 모델 변경이나 패키지 업그레이드로 시작하지 않는다.
- 브라우저에서 시간순 VIDEO 모드로 추론한다. 전체 영상과 관절 결과를 외부 서비스에 보내거나 저장하지 않는다.
- 기존 최대 60초·250MB 제한과 기본 0.1초 분석 간격을 유지한다. 실제 프레임 시각과 분석 간격을 결과에 남긴다. 측정하지 않은 중간 프레임을 분석 결과로 만들지 않는다.
- 모델·WASM 파일 준비와 배포 빌드 전 준비 명령을 검증한다. 공식 모델 파일의 무결성 검사와 라이선스 기록을 유지한다.

## 4. 영상 처리 전 흐름

- 파일 검증 → 영상 디코딩 → 메타데이터 확인 → 모델 초기화 → 시간순 프레임 추론 → 관절 품질 평가 → 각도 측정 → 결과 반환을 완성한다.
- 원본 영상의 실제 가로·세로·회전된 표시 방향을 기준으로 측정하고, 종횡비를 무시한 좌표 계산을 하지 않는다.
- seek 완료와 실제 프레임 준비를 확인한다. 요청한 시각과 반환된 시각을 혼동하지 않는다. 추론 타임스탬프는 반드시 증가해야 한다.
- 모델 준비와 분석 진행 상태를 구별한다. 지원하지 않는 코덱, 빈 영상, 길이·크기 초과, 디코딩 실패, 모델 로딩 실패, 타임아웃을 해결 가능한 오류로 반환한다.
- GPU 초기화 실패 시 CPU로 재시도하고 실제 사용한 실행 장치를 기록한다. 취소와 재분석을 지원하며, 취소한 이전 결과가 새 결과를 덮어쓰지 않게 한다.
- 성공·실패·취소 모든 경로에서 모델, 이벤트 리스너, 영상 객체, Object URL 등 자원을 정리한다.
- 프레임 사이에 UI 처리를 양보한다. Worker는 실제 측정에서 UI 지연이 문제일 때만 도입한다. 동기 추론 중 즉시 취소가 불가능한 경우 그 한계를 정확히 표시한다.

## 5. 33개 관절 추적 상세

- 공식 인덱스와 사람이 읽을 수 있는 이름을 연결하고 좌우를 명확하게 구분한다. 얼굴 기준점, 양쪽 어깨·팔꿈치·손목·손 기준점·골반·무릎·발목·뒤꿈치·발끝을 모두 반환한다.
- 각 관절에 모델 원본 좌표 x/y/z, visibility, 해당 프레임의 유효 상태와 실패 이유를 제공한다. x/y는 영상 정규화 좌표이며 z를 실제 거리로 해석하지 않는다.
- 양쪽 관절 데이터를 보존한다. 측정하기 편한 쪽 하나만 반환하거나, 장면마다 좌우를 바꾸어 하나의 궤적으로 합치지 않는다.
- 관절별 상태는 관찰 가능, 가림·저신뢰, 화면 이탈, 잘못된 좌표 등으로 설명 가능하게 만든다. visibility를 정확도 백분율이나 오차 범위로 표시하지 않는다.
- 한 사람의 분석을 유지한다. 여러 사람이 잡히거나 대상이 바뀐 것으로 의심되는 구간은 표시하고 정상 측정으로 사용하지 않는다. 영상만으로 인물의 동일성을 완벽히 확인한다고 주장하지 않는다.
- 프레임 간 갑작스러운 좌표 도약이나 길이 변화는 의심 구간으로 표시한다. 빠른 실제 동작과 오추정을 같은 것으로 단정하지 않고 원본 좌표를 남긴다. 임계값과 적용 조건을 기록한다.
- 누락 관절을 이전 프레임으로 채워 관찰된 관절처럼 반환하지 않는다. 재등장 시 끊어진 추적 상태를 명확히 처리한다.
- 별도 흔들림 필터는 필수 구현이 아니다. 실제 영상에서 흔들림이 주요 실패 원인으로 확인되고 시간이 남을 때만 적용한다. 적용하면 원본과 보정값을 구분하고 빠른 동작의 지연·피크 손실을 비교한다.

## 6. 부위별 측정과 유효성

- 기존 trunk/neck/knee/upperArm/lowerArm/wrist 연결을 보존하면서, 양쪽 팔과 양쪽 다리의 측정 결과를 각각 제공한다. 필요한 공유 타입 변경은 호출부와 예시 데이터까지 함께 반영한다.
- 몸통 기울기, 목의 영상 평면상 상대 기울기, 좌우 위팔의 몸통 대비 기울기, 좌우 팔꿈치·무릎 굽힘, 관찰 가능한 손목 근사 각도를 계산한다.
- 계산마다 사용한 관절, 단위, 기준축, 중립 기준, 부호와 유효 범위를 문서화한다. 좌우 반전·세로 영상에서도 같은 물리 자세가 일관되게 측정되는지 확인한다.
- 어깨·골반의 좌우 기준점과 신뢰할 수 있는 신체 분절은 결과에 남긴다. 추가 골반·발목·몸통 측면 측정은 현재 모델과 촬영 방향에서 정의·검증 가능한 영상 평면상의 값만 제공한다.
- 원근, 비틀림, 화면 밖 방향 때문에 관찰할 수 없는 값은 null과 이유로 반환한다. 2D 기울기를 해부학적 회전이나 실제 3D 각도로 이름 붙이지 않는다.
- 한 관절이 가려졌다는 이유로 모든 부위의 측정값을 없애지 않는다. 각 측정에 필요한 관절만 평가해서 부위별 유효성·부분 분석 상태를 제공한다. 사람 없음·다중 인물 같은 전체 실패는 별도로 처리한다.
- 손목은 현재 Pose 모델의 손 기준점으로 가능한 근사치임을 명시하고, 근거가 부족하면 사람 확인 필요로 남긴다. 목 중립 보정은 실제 기준 장면에서 확인한 값만 사용한다.

## 7. 품질과 프론트엔드 계약

- 관절 단위, 측정값 단위, 프레임 단위, 영상 단위의 상태를 구분한다. 영상 일부 실패를 전체 성공률로 숨기지 않는다.
- 결과에는 영상 크기·길이·분석 간격, 모델 버전, 처리 시각, 실제 장면 시각, 인물 수, 관절 좌표·상태, 양쪽 부위 측정값·근거, 유효 장면 비율, 부위별 측정 가능 비율과 실패 이유를 포함한다.
- raw 데이터가 정상인 것처럼 보이도록 임의 보간하거나 불확실한 값을 0도로 바꾸지 않는다. 빈 값과 실제 0도는 구별한다.
- 부분 측정과 기존 ready/retake 상태의 의미를 문서화한다. 임계값은 앱 품질 설정이며 법정 기준으로 표현하지 않는다.
- 프론트엔드가 영상 위에 뼈대를 정확히 겹칠 수 있게 영상 좌표와 표시 좌표의 변환 방법을 제공한다. object-fit 여백, 반전, 리사이즈가 좌표와 각도에 중복 적용되지 않게 한다.
- 장면을 선택하면 해당 시각의 원본 영상과 관절·각도·신뢰도·실패 이유가 함께 바뀌어야 한다. 정상 관절과 불확실한 관절을 시각적으로 구별할 정보를 제공한다.
- 제품 화면이 준비돼 있으면 필요한 최소 연결만 한다. 아직 없다면 충돌하지 않는 작은 엔진 확인 화면을 만들어 파일 선택·진행률·뼈대·시각 선택·각도 확인을 가능하게 한다. 제품 전체 화면을 별도로 만들지 않는다.

## 8. 검증을 실제로 실행

이 goal은 아래 구현 검증과 관련 테스트 실행을 요청한다.

- 합성 좌표로 알려진 각도, 좌우 반전, 영상 종횡비, 양쪽 독립 측정, 관절 누락·가림, null 처리, 잘못된 좌표, 중복 시각을 검증한다.
- 브라우저에서 실제 모델 파일을 불러와 영상 추론을 실행한다. 함수 존재·타입 검사·모킹 결과만으로 실제 추론 성공을 대신하지 않는다.
- 정상 옆모습, 부분 가림, 몸 일부 잘림, 사람이 없는 영상, 다중 인물, 빠른 팔 움직임을 가능한 자료로 확인한다. 자료가 없는 조건은 미검증으로 남긴다.
- 반복 분석, 중도 취소 후 재분석, GPU 실패 후 CPU 처리, 영상 좌표와 뼈대 오버레이의 정렬을 확인한다.
- 팀이 제공한 영상에서 사람이 표시한 관절 위치·각도와 비교한다. 좌표 오차와 각도 오차, 부위별 측정 가능 비율, 실패 장면 수와 처리 시간을 기록한다. 기준 라벨 작성자·장면 수·분모·측정 방법을 남긴다.
- 기준 라벨은 엔진 결과를 그대로 정답으로 옮기지 않는다. 기준값이 없으면 추론 성공과 정확도 검증을 분리해 보고한다.
- 수정에 사용한 장면과 확인용 장면을 구분한다. 개선 전후를 말할 때는 같은 조건과 동일 장면으로 비교하고 실패 사례도 남긴다.
- 사용자 영상이 없으면 한 번 요청하고, 모델 실행·좌표 계산·화면 연결 등 가능한 작업을 계속한다. 필요하면 출처와 이용 조건이 확인된 공개 영상으로 실행을 확인하되 팀 작업 영상의 정확도 증거로 바꾸지 않는다.
- 타입 검사와 관련 테스트를 통과시킨다. 실제 프론트엔드가 있으면 배포 빌드와 모델 자산 로딩도 확인한다. 개인정보가 있는 영상·결과·인증정보를 Git과 로그에 넣지 않는다.

## 9. 우선순위와 반복 방식

1. 실제 영상 한 편의 로딩·추론·결과 반환을 끝까지 성공시킨다.
2. 양쪽 33개 관절과 부위별 부분 측정·품질 상태를 완성한다.
3. 화면과 엔진 계약을 연결하고 실제 영상·뼈대·수치의 정렬을 확인한다.
4. 가림·이탈·다중 인물·실패·취소 경로를 보강한다.
5. 실패 사례를 재현해 원인을 고치고 정확도·속도 결과를 남긴다.
6. 문서·관련 테스트·실행 방법·PR을 정리한다.

각 단계에서 확인한 사실, 실패 사례, 다음 수정 이유를 짧게 기록한다. 검증되지 않은 옵션을 늘리지 말고 현재 데모를 막는 실패부터 고친다. 16:00 이후에는 새 모델·새 라이브러리·새 기능을 시작하지 않는다. 시간이 부족하면 핵심 흐름과 데이터 신뢰성을 우선하고 남은 요구사항을 미완료로 적는다.

## 10. 완료 기준과 인계

다음 조건을 항목별 증거와 함께 확인했을 때만 완료로 판단한다.

- 실제 영상 파일이 브라우저에서 끝까지 분석된다.
- 신체 33개 관절과 양쪽 측정값이 정의된 계약대로 전달된다.
- 관절·부위별 불확실성을 보존하고 부분 측정과 전체 실패를 구별한다.
- 정상 영상과 최소 한 가지 실패 사례가 화면 또는 재현 가능한 엔진 확인 화면에서 동작한다.
- 관련 테스트와 타입 검사가 통과하고, 실제 모델 실행 기록이 있다.
- 준비·호출·좌표 변환·오류·검증 결과가 docs/ENGINE.md에 반영된다.
- 정확도 비교에 필요한 기준 자료가 있으면 결과를 기록한다. 없으면 정확도 검증 미완료로 남기고 요청할 자료를 명시한다.
- 수정 코드와 호출부가 빠짐없이 커밋돼 PR로 검토 가능하다. 병합과 서비스 배포는 기존 승인 범위에 맞춰 진행한다.

계획 수립, 문서 작성, 타입 검사만으로 엔진 완성을 선언하지 않는다. 외부 권한·영상·기준 라벨 등 때문에 일부 검증을 할 수 없으면 가능한 구현을 마친 뒤 증거, 시도한 해결책, 남은 항목과 필요한 입력을 보고한다. 마감이 가까워졌다는 이유로 미완료를 완료로 바꾸지 않는다. goal 상태는 실제 도구의 상태 전환 조건에 맞춰 관리한다.

마지막 보고에는 구현한 범위, 변경 파일·PR, 실행 명령, 검증 결과·장면 수, 아직 확인하지 않은 한계와 프론트엔드 연결 방법을 포함한다.
