GPU→CPU 검증은 **GPU 생성 함수에만 예외를 주입**했다. CPU SDK·모델·프레임 추론을 모킹하지 않았다. 실제 GPU 고장 장비를 시험한 것은 아니다. WebGL 컨텍스트를 모두 끈 별도 실험에서는 CPU 경로도 영상 추론에 실패했다. CPU delegate라는 이름이 브라우저 그래픽 기능 전부 불필요함을 뜻하지 않는다.

원본 영상은 반대쪽 팔을 몸이 가리는 장면이 많다. 오른쪽 위팔·팔꿈치·손목 측정 가능 비율은 각각 **7/79(8.86%)**였다. 왼쪽은 이 세 값이 79/79다. 보이지 않는 쪽을 보이는 쪽 값으로 채우지 않았다. `ready`와 양쪽 모든 측정 가능을 구별해야 한다.

전체 159장면은 원본 79 + 검은 영상·crop·다중 인물·직사각형 가림·CPU 각각 10 + GPU 재분석 3회 각 10이다. 별도의 취소 중 처리한 장면은 이 합계에 넣지 않았다. 원본을 가공·재분석한 자료이므로 독립적인 실제 작업 영상 159장면이라고 발표하지 않는다.

## 화면·복구·자원 확인

`scripts/verify-browser.cjs`의 assert로 다음을 확인했다.

- 장면 20 선택 시 영상과 분석 시각 모두 2.00초. Canvas backing은 480×640, 영상과 Canvas의 화면 영역은 모두 640×853.328125 CSS px. 실제 스크린샷에서 뼈대가 인물 위에 정렬되는 것을 확인했다.
- 방향을 바꿔 원본 좌표로 다시 측정하고 결과·요약을 갱신한다. 모델을 다시 실행하지 않는다.
- 각 분석 장면에 33개 관절 이름/상태와 좌우 6개 측정 항목이 있다. 화면 측정 표는 12행이다.
- 추론 진행 중 취소: 결과를 적용하지 않고 취소 상태로 복귀. 다음 원본 영상 분석 성공.
- 모델 경로 404: GPU와 CPU 초기화 모두 실패하는 상태를 표시하고 결과를 비움. 경로를 복구한 다음 분석 성공.
- 모델 요청을 지연시킨 준비 중 취소 후 재분석 성공. 늦게 도착한 모델의 close는 별도 단위 테스트로도 확인.

## 관측한 실패와 한계

1. **실제 위치 정확도는 미검증.** 사람 라벨 작성자·원본 관절 좌표·각도 기준값이 없다. 좌표/각도 오차, 정확도 개선율, 손 채점 일치율을 계산하지 않았다. 팀 영상이 들어오면 수정용/확인용 장면을 나눠 독립 라벨에 비교한다.
2. 가려진 머리·어깨에 대해서도 모델이 높은 visibility를 반환했다. threshold를 통과했다는 이유만으로 관찰됐다고 확정할 수 없다. 목·손목과 가림 의심 장면은 사람이 원본을 확인해야 한다.
3. 처음 만든 다중 인물 fixture는 화면 안 인물이 작아 두 명 검출을 시험하지 못했다. 인물 주변 240×240 crop 두 개를 나란히 배치한 자료에서 두 명 검출을 확인했다. 실제 혼잡한 작업장 검출 성능을 의미하지 않는다.
4. 최초 GPU 추론 한 번이 약 **3.530초** 동안 메인 스레드를 막았다. 프레임 사이 취소·진행률은 동작하지만 첫 추론 중에는 즉시 반응하지 않는다. Worker는 추가하지 않았고 확인 화면에 이 제한을 표시했다.
5. 강제 SwiftShader를 사용한 이전 실행은 같은 79장면이 약 45.14초였다. 위 6.532초는 강제 SwiftShader 없이 같은 PC의 Chrome을 사용한 값이다. 하드웨어·브라우저를 바꾼 성능 보장은 아니다.
6. 장면 시각은 브라우저 seek 위치다. 원본 디코더 PTS·프레임 번호의 독립 정합성, 회전 메타데이터, Safari/iPhone, 빠른 팔 동작, 실제 산업 작업 영상, 제품 화면과 서비스 배포는 미검증이다.
7. 미검출 인물이 없다는 보장과 완전한 동일 인물 판정은 없다. 다중 인물 뒤 또는 골반 이동으로 대상 교체가 의심된 뒤에는 이후 장면도 정상 측정으로 복귀하지 않는다. 한 사람 구간으로 잘라 새로 분석한다.
