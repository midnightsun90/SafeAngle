## 1. 가장 먼저 볼 제출 조건

**개발과 제출 마감은 10월 9일 17:00(KST)**입니다. 지정된 제출 시스템에 접수된 시각이 기준입니다. GitHub에 푸시하거나 파일을 준비하는 것만으로 제출이 끝나지 않습니다.

| 필수 항목 | 공식 요건 | 우리 팀 준비 사항 |
| --- | --- | --- |
| 저장소 + 커밋 SHA | 시작할 때 등록한 동일 저장소, 심사할 커밋 지정 | [SafeAngle](https://github.com/midnightsun90/SafeAngle), 최종 SHA 기록, 심사자 접근 권한 |

| 발표용 PDF | 마감 전 최종본 제출, 운영진이 발표에 사용 | 4분 발표 구성, 화면 캡처, 검증 결과와 미확인 가정 |

함께 공개할 내용은 사전 작업과 당일 새 구현·개선·검증의 구분, 외부 자산의 출처와 활용 범위입니다. 녹화 데모와 오프라인 발표자료도 준비하도록 안내돼 있습니다. 녹화본의 별도 업로드 방식은 공개 페이지에 명시돼 있지 않습니다.

17:00 이후 추가·지각 제출, 제출물 수정은 받지 않습니다. 제출한 커밋 이후의 변경도 심사 대상에 포함되지 않습니다. 17:00–17:10은 운영진 점검 시간이며 추가 개발·제출 시간이 아닙니다. 발표 일정 지연이 마감 연장을 뜻하지 않습니다.

### 실제 접수 화면 (10/9 브라우저 확인)

플랫폼의 행사 정보는 **제출 화면에서 팀 인증과 Repository 제출을 한 번에 진행하는 방식**을 안내합니다. 별도의 사전 실시간 추적·등록 화면은 확인되지 않았습니다. 제출 마감은 플랫폼에서도 10/9 오후 5시로 표시됩니다.

1. 팀 번호를 확인하고 스태프에게 **6자리 제출 코드**를 받습니다. 코드는 README·Git·공유 문서에 넣지 않습니다.
2. [제출 화면](https://hackathon.pseudolab-devfactory.com/events/devday-seoul-2026/submit)에서 코드를 입력하고 인증합니다.
3. Repository URL과 인증 후 나타나는 필수 항목을 각각 제출합니다. 인증 전 안내에는 **ZIP과 PDF 합계 최대 500MB**, 필수 항목을 모두 제출하면 완료되는 방식이 표시돼 있습니다.
4. 행사 정보에 따르면 같은 팀 인증 정보로 마감 전까지 Repository URL을 변경할 수 있습니다.
5. 화면의 **제출현황**에서 각 항목의 접수 상태와 최종 완료 여부를 확인합니다.

여기서는 코드 입력·인증·업로드·제출을 하지 않았습니다. 인증 뒤의 정확한 필드와 파일 구성은 아직 읽지 않았습니다. 공개 규정의 Codex 기록·PDF·데모·커밋 SHA 요건을 준비하되 실제 입력·업로드 위치는 인증 후 화면에 맞춥니다. **Repository만 제출하면 Codex 로그까지 자동 수집된다는 설명은 확인되지 않았습니다.** 로그는 자동 수집을 가정하지 말고 제출 가능한 형태로 준비합니다.

## 2. 확인된 절차와 남은 세부 정보

실제 플랫폼에서 확인한 사항은 아래에 반영했습니다. 나머지는 **인증 후 화면, 이미 도착한 참가자 메일과 현장 공지**에 맞춥니다. 여기서는 해당 메일 원문을 읽지 않았습니다.

| 확인할 항목 | 공개 페이지에서 확인된 범위 | 팀 상태 |
| --- | --- | --- |
| 제출 플랫폼과 팀 인증 | 위 제출 페이지, 팀 번호·스태프의 6자리 코드 안내 | 플랫폼 URL과 인증 절차 확인, 실제 제출은 미완료 |
| 파일명·저장 위치·데모 제출 형식 | 각 필수 항목 별도 제출, ZIP·PDF 합계 최대 500MB | 인증 뒤 정확한 항목·형식 확인 필요 |
| Codex 기록 | 공개 규정의 필수 제출물 | 자동 수집 미확인, 실제 업로드 방식 확인 필요 |
| 제품에 연결할 AI 모델·API | 개발 도구 규정과 별개로 최종 안내 대상 | OpenAI API 및 MediaPipe 포즈 모델 허용 범위 대조 필요 |
| Repository 제출과 접근 권한 | 실제 플랫폼은 팀 인증과 Repository 제출을 같은 화면에서 처리 | 최종 URL·심사자 접근 권한 확인, 별도 사전 등록 화면은 확인되지 않음 |
| 세부 배점 | 6개 공통 기준과 트랙 관점 공개 | 점수·가중치는 별도 안내 확인 필요 |

| 좌석·현장 이용 조건 | 팀별 별도 안내 | 현장 공지 확인 |

이 저장소는 최초 복제 시 GitHub가 빈 상태였음을 확인했고 이후의 작업 이력을 유지합니다. 사전 공개 규정에는 시작 시 빈 저장소 등록 원칙이 남아 있지만, 실제 플랫폼에는 제출 화면에서 인증과 Repository 제출을 함께 하는 흐름이 안내돼 있습니다. **별도 사전 등록을 반드시 먼저 해야 한다고 단정했던 기존 안내는 수정했습니다.** 접수는 실제 플랫폼 안내에 따라 마감 전에 완료하고, 사전 자료와 당일 작업의 구분은 계속 기록합니다.

## 3. 개발·자료·협업 규정

### 개발 도구

- AI 코딩은 Codex만 허용됩니다. 타 AI 코딩 에이전트나 코딩 보조 기능이 확인되면 팀 참가가 무효 처리됩니다.
- 일반 IDE, 터미널, 컴파일러, 패키지, DB, Git/GitHub, 클라우드, 외부 API와 빌드·테스트·배포 도구는 사용할 수 있습니다. 이들 도구에 붙은 다른 AI 코딩 보조 기능은 끕니다.
- 개발 도구·과정·관련 기록을 설명해 달라는 요청에 대비해 실제 작업 기록을 남깁니다.
- README에 기록된 주최 추가 안내에 따라 서브에이전트도 Codex만 사용합니다. 이는 10/9 팀장이 전달한 안내이며, 공개 사이트 본문과 출처를 구분해 기록한 항목입니다.

### 저장소와 사전 작업 (사전 공개 규정)

- 사전 공개 규정에는 시작 시 코드와 커밋 이력이 없는 새 GitHub 저장소 등록, 자동 README·라이선스·gitignore 미생성 원칙이 있습니다. 실제 플랫폼 접수 흐름은 위의 '실제 접수 화면'에 따로 기록했습니다.
- 등록 이후 해당 저장소에서 작업하고 마지막 제출까지 같은 저장소를 사용합니다. 커밋 이력을 삭제·재작성해 개발 과정을 숨기지 않습니다.
- 사전 코드·자료와 기존 프로젝트는 빈 저장소 등록 후 반영할 수 있습니다. 사전 기능·코드·디자인·데이터·장비와 시작 시점의 구현 상태를 공개합니다.
- 당일에 새로 구현·개선한 기능과 검증을 설명합니다. 사전 작업을 당일 작업처럼 적거나 출처를 누락·허위 기재하면 감점 또는 심사 제외 대상이 될 수 있습니다.
- 외부 라이브러리, 템플릿, 데이터셋, 모델 등은 출처·이용 조건·활용 범위를 남깁니다. SafeAngle은 도입한 포즈 모델과 REBA 규칙 자료, 실제 사용하는 패키지와 영상 자산을 목록화합니다.

### 사람·자료·현장

- 팀은 1–4명이고 한 사람은 한 팀에만 속합니다. 시작 후 팀원 추가·이동은 허용하지 않으며 불참·중도 이탈은 운영진에 알립니다.
- 계정 공유, 대리 개발, 다른 팀이나 팀 외 인력이 코드 작성을 대신하는 방식은 허용하지 않습니다.
- 타인의 작업, 개인정보와 비공개 자료를 무단으로 사용·공개하지 않습니다. 제출 로그, PDF, 저장소에서 키·개인정보·회사 기밀을 점검합니다.
- 하드웨어는 선택 사항입니다. 사용하면 직접 준비하고 전원·네트워크·공간·동작 조건을 사전에 확인합니다. 촬영도 현장 출입·보안·공간 지침을 따릅니다.

## 5. 심사 기준과 SafeAngle이 준비할 근거

다음 표의 왼쪽은 공식 심사 기준, 오른쪽은 **우리 팀의 준비 제안**입니다. 배점은 공개 페이지에 없습니다.

| 공식 기준 | SafeAngle에서 보여 줄 근거 |
| --- | --- |
| 문제 정의와 필요성 | 대상 보건관리자, 영상 확인·평가표 작성의 실제 불편, 기존 방식과의 차이 |
| AI 판단과 해결 방식 | 포즈 모델의 관절 추정, 규칙 엔진의 채점, 언어 모델의 맥락·문장 제안, 사람 확인의 경계 |
| 작동하는 결과물 | 실제 영상 입력 → 대표 장면·점수 → 사람 수정 → 조사표 초안의 연결된 데모 |
| 검증과 개선 | 손 채점과 비교한 분모·결과, 실패 장면, 원인과 수정 전후, 남은 한계 |
| 사업성·도입 가능성 | 예상 도입자와 업무 흐름, 측정한 처리시간·비용, 아직 가정인 구매·지속 사용 조건 |
| Codex 활용 과정 | 맡긴 작업, 검토·수정·통합한 사례, 채점 검증과 개발 기록 |

Track 1은 줄이려는 위험·손실, 판단 이후 대응, 오탐·미탐·작동 실패 처리를 봅니다. SafeAngle에서는 불확실한 장면의 재촬영, 미확인 입력의 표시, AI 실패 시 기본 초안, 최종 조사자 확인을 시연 근거로 준비합니다.

팀 규모·장비 가격·토큰 사용량 자체는 점수 대상이 아닙니다. 품질을 유지하면서 비용·대기시간·반복 업무를 줄인 경우 근거를 설명합니다. 하루 안에 사업이나 현장 효과를 모두 입증할 필요는 없지만, 확인한 결과와 아직 검증하지 않은 가정은 구분합니다. DevDay 기술 소개의 모든 기능을 사용할 필요는 없습니다.
