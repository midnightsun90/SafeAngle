## 1. 목표와 우선순위

핵심 결과는 **한 장면의 측정 → 사람 확인 → REBA 점수와 근거**다. 현재 엔진의 실행 성공을 점수 검증이나 관절 정확도로 바꾸지 않는다.

1. 최신 저장소와 실제 호출부를 확인하고 변경 범위를 정한다.
2. REBA 규칙·표·공유 입력/출력과 경계 정책을 구현한다.
3. 엔진의 한 장면을 채점 입력에 연결한다.
4. 기존 프론트엔드에 최소 확인 질문·결과 표시를 연결한다.
5. 실제 영상과 실패 사례로 전체 흐름을 실행해 수정한다.
6. 문서·검증·PR을 정리한다.

세 영상 후보를 지원하는 팀 흐름을 보존하되 영상 한 편의 성공을 먼저 확보한다. 화면이나 데이터에 여러 영상이 있으면 각각 평가하고, 목·팔·다리를 서로 다른 영상이나 시각에서 모아 한 점수로 만들지 않는다. 실제 업무에 해당하지 않는 촬영 유형을 채점 조건으로 강제하지 않는다.

## 3. 규칙을 코드로 고정

### 기준과 계산

- 부위별 기본점수와 목·몸통·팔·손목 가감을 `evaluation-axes.md`에서 가져온다.
- 그룹 A: 목·몸통·다리 → 표 A → 하중·힘 및 충격 가산.
- 그룹 B: 평가할 쪽의 위팔·팔꿈치·손목 → 표 B → 손잡이 상태 가산.
- 표 C(점수 A×점수 B) + 활동 0~3 → 최종 점수와 문서의 조치 수준.
- 표 A 60칸, B 36칸, C 144칸의 행·열 방향과 모든 값은 문서와 대조한다. 단순 합계가 맞는 것만으로 표가 맞다고 판단하지 않는다.
- 책·강의 자료의 차이를 팀 문서가 이미 처리한 부분은 그 선택을 기록하고 일관되게 적용한다. 새로운 충돌이 발견되면 저자 원문·공식 출처를 확인하고 근거 없는 규칙을 만들지 않는다.

### 경계·보정에서 빠뜨리지 않을 것

- 중복 표기된 몸통 20° 및 위팔 20°·45°를 명확한 비교 연산자로 만든다. 원문으로 해소되지 않으면 공유 경계는 낮은 점수 구간에 넣는 **앱의 경계 정책**을 기록하고 양쪽 경계 테스트를 둔다. 이를 원문에 명시된 사실로 표현하지 않는다.
- 무릎 30°·60°, 아래팔 60°·100°, 손목 15°, 하중 5·10kg, 정지 1분, 반복 분당 4회의 이상/초과를 문서대로 적용한다.
- 몸통의 '똑바로 섬'과 목 중립을 임의 ±각도로 판정하지 않는다. 독립 기준 장면이 없으면 실제 장면에서 사람이 중립/점수 구간을 확인할 수 있게 하고 보정 미완료 상태를 표시한다. 각도 부호와 중립 해석은 샘플 장면에 대조한다.
- 팔 지지 −1 뒤 표 B 범위를 벗어나는 0점이 생기는 경우를 처리한다. 저자 근거와 표의 입력 범위를 확인하고 필요한 최소 1점 정책을 명시한다. 점수를 범위 안으로 임의 자르는 일반 clamp로 입력 오류를 숨기지 않는다.
- 앉은 자세의 무릎 가산은 적용하지 않는다. 다리 지지와 불안정한 지지면을 독립적으로 보존한다.
- 팔 벌림·회전과 어깨 상승은 별도 가산, 목의 비틀림/옆 기울임·몸통의 비틀림/옆 기울임·손목의 옆 꺾임/회전은 각 부위 문서의 한 번 가산 조건을 지킨다.
- 문서의 손잡이 '해당 없음'은 취급·지지 물체가 실제로 없음을 확인한 경우다. 물체가 있는데 손잡이가 없음과 구별한다.

## 4. 입력·출력 계약

- 평가의 키는 영상 ID, 장면 시각, 평가할 사람 기준 쪽이다. 동일 장면·동일 쪽의 측정만 사용한다.
- 각 입력의 값, 출처(영상 측정/사람 확인), 확인 상태와 이유를 보존한다. `미확인`, `확인 불가`, `해당 없음`, 실제 0을 구별한다.
- 필수 입력 누락, 비정상 숫자·범위·선택지, 관찰 불가 장면을 검증한다. 외부에서 호출 가능한 함수 입력을 타입 선언만으로 신뢰하지 않는다.
- 측정과 사람이 확인한 점수 구간은 구별한다. 사람 확인값은 저장할 수 있지만 원본 측정·null·실패 이유를 덮어쓰지 않는다.
- 출력에는 완료/확인 필요/측정 불가 상태, 누락 항목, 부위별 기본·가감·최종 부위점수, 표 A/B/C 조회값, 하중·손잡이·활동 가산, 최종 REBA·조치 수준과 근거 ID를 둔다.
- 필수 입력이 모두 확인되기 전에는 최종 확정 점수와 조치 수준을 null로 둔다. 계산할 수 있는 부위별 근거는 유지한다. 같은 입력은 항상 같은 결과를 낸다.
- `requiresReview`, 다중 인물, 비측면 등 채점 불가 장면의 원인을 사람 입력으로 덮어 자동 정상화하지 않는다. 확인 가능한 장면의 특정 부위 실패에만 문서의 보충 질문을 적용한다.
- 목·손목 근사치는 사람 확인 필요를 유지한다. null을 0도나 최저점으로 바꾸지 않는다.

## 5. 실제 프론트엔드 연결

기존 회사·작업 정보 화면과 디자인을 활용해 다음 최소 흐름을 만든다.

1. 작업 정보 보존 → 영상 파일 선택·미리보기.
2. 실제 `analyzeVideo` 호출 → 준비/분석 진행 상태·취소·오류.
3. 영상·장면·평가할 쪽 선택 → 해당 시각 뼈대·양쪽 측정·누락 이유.
4. 선택 장면의 Q1~Q4 및 필요한 보충 질문 → 확인 상태 표시.
5. 같은 계산 모듈 호출 → 부위별 근거·점수 A/B/C·활동·최종 점수·조치 수준.

- 처음부터 '아니요'·최저 하중·양호 손잡이를 확인한 값으로 채우지 않는다. 사용자가 확인하도록 한다.
- 작업 조건이 같은 경우 Q2~Q4 재사용을 허용하되 재사용 상태를 표시한다. 새 장면의 쪽·다리 지지·손목 등 자세별 답을 무조건 복제하지 않는다.
- 입력·장면·쪽·영상 변경 시 결과를 다시 계산하거나 확인 필요로 바꾸고, 오래된 확정 점수·근거가 남지 않게 한다.
- 대상 교체 의심 구간을 정상 점수 그래프에 넣지 않는다. 여러 장면의 최고점을 대표로 표시하면 최고점인 사실과 그 장면을 함께 표시한다. 아직 확인하지 않은 장면에 같은 답을 일괄 적용해 최고점을 만들지 않는다.
- 모델 자산 준비는 프로젝트의 실제 Next.js `frontend/public` 경로와 맞춘다. 기존 root의 `public` 준비만으로 frontend에서 로딩된다고 가정하지 않는다.
- 공통 `lib`를 복사하지 않고 import한다. frontend의 TypeScript import 확장자·Turbopack root·의존성 경계를 확인하고 최소 설정으로 연결한다. 모델·WASM은 빌드 전에 준비하고 실제 서비스 경로에서 로딩을 확인한다.
- 원본 영상과 Canvas의 fit·반전·seek를 같은 기준으로 사용한다. 취소·재분석·화면 해제 시 자원을 정리한다. 첫 동기 추론 중 취소 지연 한계를 표시한다.

## 6. REBA와 다른 평가축의 구별

- B01~B11, S01~S16, V01~V05를 REBA에 가산하지 않는다.
- V는 관찰·채점 가능성, B는 별도 현장 조건, S는 조사표·현장 기록이다. 결과 문구와 데이터에서 구별한다.
- `docs/criteria.md`와 적용 버전의 공식 고시 수치가 없으면 법적 부담작업 해당 여부는 미확인으로 남긴다. REBA 흐름을 이 별도 작업 때문에 멈추지 않는다.
- 건강·증상·개인 이력은 영상으로 추정하지 않는다. 현재 최소 평가 흐름을 위해 해당 정보를 추가 수집하지 않는다.
- REBA 점수가 나왔다고 유해요인조사 전체 완료를 표시하지 않는다. 기존 조사표 출력이 준비되어 있으면 확인된 자세 결과만 연결하고 누락 칸·초안 상태를 유지한다. 조사표 전체나 생성형 API를 새로 만드는 작업으로 확대하지 않는다.

## 7. 검증을 실행

이 Goal은 관련 테스트·타입 검사·빌드·실제 브라우저 검증을 명시적으로 요청한다.

### 계산 검증

- 저자 예제 A=8, B=5, C=10, 활동 +1 → 최종 11점. 최종 숫자만이 아니라 부위점수·가산·조회 과정을 확인한다.
- 표 A/B/C의 문서 값과 실제 데이터가 모든 칸에서 일치하는지 대조한다. 구현 테이블을 그대로 정답 테이블로 복사한 테스트만 두지 않는다.
- 각 구간의 바로 아래/동일/바로 위, 앞굽힘·뒤젖힘, 머리 위 팔, 앉은 자세, 팔 지지 감점, 가산 조건 중복 방지와 활동 경계를 확인한다.
- 미확인·null·NaN·잘못된 enum·범위·쪽·장면 혼합·원본 변경 방지·입력 변경 후 재계산을 확인한다.
- 기존 관절 추적 테스트·타입 검사를 통과시키며 기존 `angles`와 양쪽 `measurements` 계약을 보존한다.

### 연결·브라우저 검증

- 실제 frontend 타입 검사와 프로덕션 빌드를 실행한다. root 엔진 타입 검사 성공으로 대신하지 않는다.
- 빌드 실행 환경에서 모델·WASM을 실제로 로딩하고 Chrome으로 영상 추론한다. SDK 모킹으로 대신하지 않는다.
- 영상 한 편 → 장면/쪽 → 질문 확인 → 최종 점수의 흐름을 실제 실행한다. 같은 장면의 입력 하나를 바꿔 점수/근거가 갱신되는 것을 확인한다.
- 미확인 입력 하나 남기기, 측정 실패, 사람 없는 영상 또는 다중 인물, 취소 후 재분석, 새 파일에서 이전 결과 제거를 확인한다.
- 사람 기준 라벨이 있으면 엔진 결과를 보지 않고 작성한 정답과 대조해 좌표·각도·점수의 차이를 각각 기록한다. 라벨이 없으면 공개 영상으로 실행을 확인하고 정확도 미검증으로 남긴다.
- 공개 영상은 기존 출처·이용 조건을 따르고, 개인 영상·키·제출 코드·전체 사용자 결과를 Git이나 공유 로그에 넣지 않는다.

## 8. 작업·인계·완료

- 별도 브랜치에서 최신 팀 변경을 보존하고, 단계마다 성공/실패와 다음 수정 이유를 기록한다. 팀 파일이 바뀌면 호출부와 계약을 다시 대조한다.
- 마감 17:00 KST, 16:00 기능 고정, 16:30 검토 가능한 결과를 작업 목표로 둔다. 실제 현재 시간을 확인해 우선순위를 조정한다. 이후에는 새로운 모델·라이브러리·제품 기능을 추가하지 않는다.
- 규칙/경계 정책, 공유 계약, 화면 연결, 자산 준비/빌드 명령, 실행·실패 증거와 남은 항목을 `docs/REBA.md` 등 작은 인계 문서와 README에 남긴다. 이미 있는 적절한 문서는 재사용한다.
- 구현·연결·관련 테스트·문서를 커밋해 검토 가능한 PR을 만들고 이 채팅에 첨부한다. #11 병합 승인은 처리됐으며 새 PR 병합이나 서비스 배포까지 승인된 것으로 해석하지 않는다.
- 완료 여부를 실제 영상 실행, 확인 질문과 점수 갱신, 실패·미확인 처리, 타입·테스트·빌드, 재현 가능한 기록과 PR로 대조한다. 하나라도 필요한 구현이 남으면 완료라 하지 않는다.
- 외부 자료·권한이 부족하면 가능한 독립 작업을 계속하고 필요한 입력을 한 번 명확히 요청한다. 반복된 막힘은 실제 Goal 상태 도구의 조건에 맞춰 처리한다. 시간이 부족하거나 어려운 것만으로 blocked/complete로 바꾸지 않는다.

마지막 보고에는 PR·커밋, 바뀐 규칙/파일, 실행 명령, 실제 검증 장면과 분모, 사람 확인 필요·정확도 미검증·남은 법령 작업, 팀원 연결 방법을 포함한다.
