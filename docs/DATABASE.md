# SafeAngle 데이터 저장 구조

## 데이터는 이렇게 연결된다

**관리자 1명 → 평가 대상자 여러 명 → 대상자별 평가 여러 건 → 평가마다 영상 최대 3개**

관리자와 평가 대상자는 서로 다른 사람이다. 같은 대상자를 다시 평가하면 이전 기록을 덮어쓰지 않고 새 평가를 추가한다.

| 저장 항목 | 내용 |
| --- | --- |
| 관리자 | 이름, 관리자 구별 번호 |
| 평가 대상자 | 이름, 담당 관리자 |
| 평가 | 대상자, 작업 정보, 질문 답변, 영상에서 측정한 값, 점수와 결과, 진행 상태 |
| 영상 기록 | 촬영 자세 종류, 비공개 영상 파일의 위치 |

영상 파일은 `assessment-videos`라는 비공개 저장소에 둔다. 평가 기록에는 영상 파일의 **위치만** 적는다. 영상 위치는 공개 주소가 아니다. 영상 하나의 현재 업로드 한도는 50 MB다.

질문에 답하지 못했거나 영상에서 측정할 수 없는 값은 **미확인**으로 남기고 0점으로 바꾸지 않는다. 평가를 `완료` 상태로 저장하려면 결과와 REBA 점수가 둘 다 있어야 한다. 점수 기준은 [평가표](evaluation-axes.md)에 있다.

## 누가 볼 수 있나

- 관리자는 자신이 등록한 평가 대상자와 평가, 영상만 볼 수 있다.
- 다른 관리자의 기록은 볼 수 없다.
- 관리자 이름은 화면에 보여 주는 값이다. **이름이 같다는 이유로 다른 사람의 기록에 들어갈 수 없다.**
- 심사위원용 공개 시연 페이지에는 예시 데이터만 보여 준다.

## 지금까지 만든 것

- [Supabase SafeAngle 프로젝트](https://supabase.com/dashboard/project/ixocecrvriaprwynhnst)에 관리자·평가 대상자·평가·영상 기록 표 4개를 만들었다.
- 비공개 영상 저장소와 관리자별 접근 제한을 설정했다. 보안 점검 결과 오류 0건, 경고 0건이었다.
- 현재 저장된 평가와 영상은 없다.
- 웹 화면의 관리자 이름과 평가 대상자 이름은 DB에 저장된다. 같은 브라우저에서는 새로고침 후 다시 불러온다.
- 이름 입력 시 익명 로그인으로 관리자 구별 번호를 만든다. 브라우저 데이터를 지우거나 다른 기기를 사용하면 이전 기록에 다시 접근할 수 없다.

## 아직 연결하지 않은 것

- 영상 업로드와 평가 결과 저장 기능. 작업 정보와 질문 답변은 현재 브라우저에만 저장된다.
- 다른 기기에서 기존 관리자 기록에 접근할 수 있는 계정 로그인 방식.
- 영상 파일 형식 제한. 현재 저장소는 파일 형식을 제한하지 않는다.

개발용 SQL: [DB 생성 파일](../supabase/migrations/20261009044810_safeangle_core.sql). 이 SQL은 Supabase 화면에서 실행했으며, 원격 마이그레이션 이력에는 아직 등록되지 않았다. 다시 실행하기 전에 이력을 맞춰야 한다.
